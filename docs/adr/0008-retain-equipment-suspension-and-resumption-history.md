# 利用停止と利用再開の経緯を履歴として残す

機材の各利用停止について停止理由・実行者・停止日時を、各利用再開について実行者・再開日時を履歴として残す。現在の利用可否だけを上書きする案では、停止と再開を繰り返した際の判断経緯が失われ、後から復元できないため採らない。修理内容の詳細と承認フローは今回の対象に含めず、[ADR-0001](./0001-single-site-individual-equipment.md) のスコープを維持する。

履歴は実際に成立した状態遷移だけの記録とし、利用停止中の機材への再停止は「すでに停止中」、利用可能な機材への再開は「すでに利用可能」として拒否する。拒否された操作では状態も履歴も変更せず、利用停止中に別の停止理由が指定されても既存の停止理由を上書きしない。

停止理由は必須の自由記述とし、前後の空白を除去した値を記録する。空白除去後に空文字となる場合は利用停止を拒否し、停止理由の分類マスタや業務ルールとしての文字数上限は設けない。

停止日時・再開日時は、それぞれの操作が成立した時点の現在日時をシステムが自動記録し、日時の丸めやユーザーによる手入力・訂正は行わない。同じ機材の直前の利用停止・利用再開の日時と同時刻は許可し、それより前の日時となる場合は操作を拒否して状態と履歴を変更しない。

利用停止・利用再開の要求は、操作対象の確認後に同じ機材で別の利用停止・利用再開が成立していたら「確認後に状態が変わった」として拒否する。現在の利用可否が確認時と同じであっても拒否し、状態と履歴を変更せず、最新状態を確認してから再操作する。古い再開要求で、確認した停止とは別の新しい停止を解除しないためである。古い版の検出は「すでに停止中」「すでに利用可能」の判定より優先し、後者は要求の版が現在の版と一致する場合に返す。

利用停止・利用再開と予約・貸出の競合は、同じ管理番号に対する原子的な確定順で判定し、特別な優先順位や自動再試行は設けない。利用停止が先に成立すれば後続の予約・貸出を利用停止中として拒否し、予約・貸出が先に成立すればその記録を維持したまま利用停止を成立させ、既存の予約・貸出を巻き戻さない。利用再開が先に成立すれば、後続の予約・貸出は利用可能な状態として、その他の条件も含めて通常どおり判定する。

管理者が管理番号で1台を指定し、現在状態・版番号と、その版までの全履歴を成立順に取得する照会ユースケースを今回の対象に含める。Web画面、機材を横断する検索、集計、履歴の編集・削除は今回の対象に含めない。
