# 機材の現在状態と全履歴を分けて保持する

機材集約には、現在状態、次の利用停止・利用再開の判定に必要な直前の遷移情報、版番号を持たせ、利用停止・利用再開の全履歴は集約の外に追記保存する。遷移ルールは機材集約で強制し、全履歴を内包する案は、集約が履歴件数に比例して大きくなり、次の遷移に不要な過去の記録まで抱えるため採らない。

版番号は成立した利用停止・利用再開ごとに進め、要求が確認した版との照合で [ADR-0008](./0008-retain-equipment-suspension-and-resumption-history.md) の古い要求を検出する。同一日時の状態遷移の順序も、この版番号で判定する。

機材の状態更新、版番号の更新、対応する履歴追加は、同じ管理番号に対する一度の原子的な確定として扱い、一部だけが成立することを認めない。具体的なDBや永続化方式は、この集約と確定契約の判断から分離し、永続化設計時に決める。

アプリケーション層では、この契約を `EquipmentAvailabilityStore` ポートで表す。`tryChange` は原子的な境界内で最新の機材と成立時点のシステム日時を同期的な遷移判定に渡し、成功した新しい機材と履歴を一括で保存する。確定前の読み取りで日時や遷移を決めると、待機中に成立した別の操作を見落とすため、ドメインの判定もこの境界内で行う。

照会の `read` では、同じ確定時点の機材の現在状態・版番号と、その版までの利用停止・利用再開履歴を一組として返す。履歴は版番号の昇順とし、読み取り中に新しい遷移が成立しても、異なる版の状態と履歴を組み合わせない。

今回のテスト用保存処理は公開ユースケースとポート契約を確認するものであり、実DBの原子性・排他制御・障害時のロールバック保証は、永続化アダプタの導入時に検証する。
