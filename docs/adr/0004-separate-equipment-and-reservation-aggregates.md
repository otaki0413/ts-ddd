# 機材と予約を別の集約にする

機材と予約を別の集約とし、予約可否は機材の状態と関連する予約を受け取るドメインポリシーで判断する。アプリケーション層が機材、関連する予約、現在日時を取得して、I/Oを行わないドメインポリシーへ渡し、成立した予約を保存する。予約可能な将来期間に上限がなく、すべての予約を機材集約へ内包すると集約が際限なく大きくなるためである。

アプリケーション層は、予約中または貸出済みで要求期間と重なる予約を取得する。取消済みと返却済みの貸出に対応する予約は取得対象から除く。予約中の候補は、処理されていなくても返却予定日時に達していれば、現在日時を受け取ったドメインポリシーが予約失効として重複判定から除く。貸出済みの候補は予約失効として扱わない。

同じ管理番号に対する最終的な予約可否確認と保存は原子的に行い、成立時点で利用開始予定日時が過去になった場合、直前に重複する予約が成立した場合、機材が利用停止になった場合は保存しない。アプリケーション層ではこの契約を `ReservationCommitter` ポートとして表し、成功、過去の開始日時、利用停止、予約重複を区別して返す。PostgreSQLでのトランザクションと機材行ロックによる実現方法、および最終判定の時点は[ADR-0011](./0011-atomic-reservation-commit-with-postgresql.md)で定める。
